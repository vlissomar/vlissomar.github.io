Project 1

Images of the Russian Empire

 In this project, I used image processing ideas taught in class to merge the three color channels in the digitized Prokudin-Gorskii glass plate images into one colorized image. In particular, important ideas were extracting features from pixels, Gaussian filters and antialiasing, and image pyramids (which I thought was pretty cool after orking with mip maps in graphics!).

Part 1: Single-Scale Alignment on Low-Res Images

  I actually overcomplicated this part a lot. My first implementation, I padded a border of 0s the width of the displacement window, because I assumed it would be very bad if the image wrapped around. I got it to not only work, but work (what I thought believed to be) very well with the images I was working with, and assumed that minor artifacts within a couple pixels was due to the use of heuristics. Evidently, that's not entirely true, as even though the first couple of .tif files worked fine, others tried to shift the color channel off entirely.
  My current implementation just lets the pixels roll right around the edges to the other side, and computes similarity on a centered rectangle of pixels in the middle. Though our scoring heuristic may rate it to be relatively more similar on account of things like color palette or repetitive textures like tiles/grass, this border will have relatively small weight or even no weight.
  Here, I also included a lazy brute force border detection pre-processing; before the change to not padding, this was very necessary to aligning for some reason. From each side, I pick a middle row or column, then march towards the center until the value of the next pixel is noticably different from the average. After averaging these estimates, I chop off a border of that size from the combined 3-channel image before splitting for processing.

Part 2: Acceleration Structure--Image Pyramids

 The tif files are much larger, which makes it very costly in time to align. That's where multi-scale image pyramids come in. Starting from the original image, I downsample by a factor of 2. To prevent aliasing, a Gaussian blur must be applied so that each pixel sampled represents not just itself, but the pixels around it that were discarded. I took the liberty of using scipy's 2D convolution function in this part. Iterative downsampling is also convenient in that the same Gaussian kernel can be reused to get to the next level. I also made some helper functions to set a good max level for the pyramid.
 To use this acceleration structure, we start from the highest level and run the single-scale alignment algorithm to find the offset. Again, each pixel at the coarse level represents many pixels at the fine level, so it speeds up our search within a displacement window significantly by covering more area. Scale the offset up and accumulate it as we move to finer levels, until it can be directly applied to the original image for alignment.
  Another thing to note is that as long as more pyramid levels can be made (within reason), the more the displacement window can be minimized, which tends to mean less matrix calculations. I can reliably run my program under a minute, and often, it takes only half that time when using a displacement window of [-5, 5].
